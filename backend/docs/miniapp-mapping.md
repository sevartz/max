# Соответствие возможностей бота и мини-приложения

Таблица сверена с текущими обработчиками и сервисами. Экран мини-приложения меняет только
представление: правила остаются на сервере, а бот продолжает работать через тот же процесс,
базу и фоновые задачи.

## Согласованность и безопасность

- Вход берётся только из подписанных MAX `initData`; API выводит user ID из проверенного поля `user.id`.
- Для чтения и изменения каналов проверяется `owner_user_id`; для рекламы проверяется владелец рекламодателя.
- Предложения блокируются от повторного действия блокировкой строки и проверкой `status`/`expires_at`. Фоновая публикация остаётся единственной существующей задачей публикации.
- Мутации мини-приложения требуют `Idempotency-Key`; сервер хранит хеш ключа и ответ, повтор запроса возвращает сохранённый результат. Старые записи удаляются через 30 дней.
- После согласия используются существующие обработчики подключения каналов; после решения по предложению мини-приложение редактирует исходную карточку бота.
- При возврате в открытое приложение данные перезагружаются; активный экран канала также актуализируется.
- Пошаговый ввод мини-приложения хранится отдельно в `sessionStorage` и не изменяет состояние `/cabinet` в боте.

Тесты перечисляют покрытие, но не заменяют проверку реального клиента MAX и подключённой среды PostgreSQL/MAX.
